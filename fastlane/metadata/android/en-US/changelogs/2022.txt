Since 0.2.1:
• Streaming: unattended streams now heal themselves through a full recovery stack — a watchdog watches the live stream and escalates through increasingly forceful restarts (from a soft restart of the streaming runtime up to restarting the whole server) when frames stall, verifying honestly even with zero viewers or a locked headless mount; a 15-minute out-of-process heartbeat revives a dead app or restarts a wedged server between checks; and a crash while nobody is watching relaunches the app automatically, backing off through a forming crash loop instead of thrashing
• Streaming: a server that reports "running" while answering nothing is caught too — a loopback probe hits the server's own /api/system and fires the recovery ladder when every flag lies; a swipe-kill stands the recovery tiers down for exactly one boot, so a stream you killed stays dead
• Camera: camera errors now carry a typed recovery verdict, so the dashboard tells "will self-heal" apart from "reboot the phone"; the web console also gains a reset-camera lever that forces a clean camera rebind
• Camera: new opt-in camera-resume prompt (off by default) — after a process death or reboot, LensCast may light the screen once with a full-screen tap to bring the camera back, the only unattended path that restores the camera on strict while-in-use devices; opt in if your mount must survive reboots with the screen locked
• Camera fix: manual ISO / exposure / zoom controls survive a recording start again — the mid-recording rebind no longer resets night settings to auto until restart, and applied controls land on the live session instead of a dead camera object (issue #18)
• Camera fix: saving the dashboard camera section no longer turns the torch off (issue #16), every non-torch write converges on the live LED state so flips from any surface stick, and the system diagnostics report the device's torch brightness ceiling — flat-LED reports are diagnosable without logcat
• Streaming: RTSP security is separately switchable — HTTPS on the web console no longer forces RTSPS; an independent RTSP TLS toggle bounces only RTSP, and ONVIF advertises the scheme it actually serves
• New: the companion remote — turn a second phone into a remote control for this camera. Pair over the web console (paste a pairing link with inline validation, confirm the TLS fingerprint) and get Live / Events / Media / System tabs, with picture-in-picture for the Live tab
• Automation: every rule gains a Run-now test button that fires the rule once and restores everything it touched — verify an automation change without waiting for the schedule or polluting the fire journals
• Web console: a reliability panel (watchdog tier, heartbeat misses and verdicts, crash-marker and give-up state) plus an App Restart button with typed modes — soft restart first, full process relaunch when needed
• Android: this release adds the Schedule exact alarms permission (android.permission.SCHEDULE_EXACT_ALARM) — exact alarms are how the heartbeat and the relaunch fire through Doze after process death. Granted at install on Android 12; on Android 13+ it is the one-time "Alarms & reminders" grant in Settings. Without it the heartbeat degrades to inexact (still Doze-delivered) alarms, and App Restart reports the missing grant instead of quitting — a dashboard tap can never darken a phone it cannot bring back
• Under the hood: the reliability runtime is wired through the streaming service with journal state gates, soft-restart acknowledgment and output re-arm are deterministic, the RTSP digest nonce cap evicts deterministically on expiry ties, and the camera top bar keeps its pinned buttons reachable while the row scrolls
