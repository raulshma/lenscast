Since 0.2.2:
• New look: Material 3 Expressive — generated brand color schemes, expressive motion that honors the system reduced-motion setting, and an optional Material You dynamic color toggle in Display settings (Android 12+)
• Automation: night_vision joins the actions — a rule now writes the same camera night mode the dashboard does, merged into the persisted settings and applied in place with the other camera-valued actions (no stream interruption); every action is catalog-declared (merge, effects, restore), so the executor interprets effect kinds instead of action ids
• Settings: each dashboard section saves in one atomic edit — the streaming PUT persists only the fields you touched, and the server's merge stays the single owner of how keys combine
• Updater: store builds gain an opt-in GitHub beta channel — enable Include Beta Releases in App Settings → Updates (off by default; F-Droid builds expose no updater) and the in-app updater then offers pre-releases automatically, ranking a beta above the stable it precedes
• Streaming fix: the encode tier owns the preview window — MJPEG and WHEP follow the resolution you set instead of staying pinned at the 720p analysis window, and a 480p rung can no longer degrade motion/ML analysis (issue #23)
• Streaming fix: your JPEG quality stays yours — battery and thermal act as ceilings now, so the 30-second power poll no longer resets a requested 100 back to the charging tier's 70 (issue #23)
• Streaming fix: dashboard previews no longer freeze about five seconds in — the server keepalives its video WebSockets past NanoHTTPD's idle read timeout, and a dropped stream reports an error the player retries instead of freezing on the last frame (issue #23)
• Streaming fix: fetching /stream or any MJPEG URL from a viewer-less process (curl, ffmpeg, an NVR) now starts the web output through the same start ladder a browser visit does, a wedged start answers 503 immediately instead of hanging the client, and MJPEG part headers can't stall behind Nagle (issue #24)
• Reliability fix: restarting from the dashboard (or via the heartbeat) can no longer interleave with a watchdog recovery and leave the server dead on every port — one choreography lock serializes the restart × recovery interleave at both entry points (issue #22)
• Automation fix: the torch action drives the LED it asks for — a request matching the stored intent while the live LED sits opposite is applied to the camera, not swallowed and reported as success (issue #21)
• Camera fix: one LED fact — the torch-touch verdict lives inside applySettings, so every settings write converges on the live LED state, and blocked-by-lock is detected by a typed verdict instead of matching display text
• Security: RTSP digest verification answers expired nonces with 401 stale=TRUE so clients re-sync instead of re-prompting, an opt-in Basic challenge serves picky clients and its compat toggle applies live without an auth re-save, and the viewer role's Basic auth is fixed
• Web console: the API contract now generates from the code — OpenAPI schemas build from the DTOs under strict fixture parity, the torch and siren schemas document the bodies the handlers actually require, and the dashboard saves stream patches directly for the server to merge
• Under the hood: the #14 fire-time re-check covers all three grace-window legs, the tier seam re-checks recording exclusivity before rebinding so a stale rebind can't tear down a session that just started, and resume/miss-count/journal-lifetime invariants became types
